System Architecture & Core Concepts

Hybrid Operator isolates operational responsibilities between a cluster-native Go Operator[cite: 1] and an analytical Python Brain[cite: 1].

Cluster Go Sensor

Runs directly inside OpenShift to stream lightweight telemetry, CSV phases, owned CRDs, and active CR counts[cite: 1].

Python Analytical Brain

Executes heavy upgrade projections, schema breaking-change analysis, and multi-variable scoring off the reconcile loop[cite: 1].

Remediation Engine

Enforces direct cluster actions, automatic namespace cleanup, and conflict resolution across subscriptions[cite: 1].

Cluster Governance & Telemetry Linter

The Go telemetry sensor actively monitors cluster state to catch OLM paradoxes, resource limits, and duplicate deployments before they cause outages.

🚨

Cross-Namespace Conflicts (OLM Split-Brain)

Detects duplicate operator packages installed globally in openshift-operators and locally in a user namespace (e.g., duplicate Data Grid instances), preventing API thrashing.

🔥

Overloaded Controller Pods

Flags operator pods experiencing high container restart counts (> 5 in 24h) or frequent OOMKilled terminations.

⏳

Pending Manual Approvals

Tracks manual InstallPlan updates waiting for cluster admin approval during maintenance windows.

👻

Orphaned Custom Resources

Identifies active Custom Resources running on the cluster after their parent operator subscription has been deleted.

Remediation & Operator Actions

Hybrid Operator provides direct cluster-side enforcement capabilities to resolve detected violations automatically or on-demand.

Conflict Resolution

Automatically identifies and safely removes local duplicate Subscriptions causing CSV reconciliation deadlocks.

Export Governance Reports

Generates signed JSON audit reports containing full cluster operator inventory, CRD counts, and upgrade risk vectors.

About the Apotheosis Team

The OpenShift Apotheosis team is a specialized engineering task force dedicated to Digital Ascension and operator lifecycle excellence within enterprise Kubernetes environments.

By architecting tools like the Hybrid Operator Framework and the Non-Stop Agent Automator (NSAA), the CAP team Customer Engineering Program's mission is to eliminate deployment friction, visualize hidden catalog paradoxes, and empower developers to seamlessly build, test, and release OpenShift operators safely and efficiently.
